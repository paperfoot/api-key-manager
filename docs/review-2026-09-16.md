# AKM review — 16 September 2026

AKM's useful abstraction is a small local transport: select a stored name, run a command, keep values out of the agent's transcript. The review found avoidable friction in streaming, subprocess cancellation, discovery, agent instructions, installation, and macOS error handling. Version 0.3.0 addresses those paths while preserving original Keychain entries and the public success envelope.

## Evidence

The review combined source inspection, public CLI/API documentation, a production audit-log sample, and local Claude/Codex command traces. Five independent review tasks covered usage extraction, framework contracts, macOS compatibility, hook preservation, and runtime regressions. Findings were checked against source and executable tests.

The production log sample excluded this repository's test activity: 2,176 records across 58 working directories, all from installed version 0.1.3. There were 1,021 `run` starts: 818 successful completions, 162 nonzero child completions, and 41 without a corresponding terminal record. An unmatched start is incomplete evidence, not proof that AKM hung. Several runs legitimately lasted minutes; child execution time cannot be attributed to wrapper overhead.

Of those runs, 166 selected multiple keys and 27 selected five or six. There were 32 raw reads, 25 masked reads, and 15 successful stdin operations. This supports keeping explicit multi-key selection and making direct secret transport easier to discover.

A bounded recent transcript sample contained 557 AKM-containing Codex shell-tool calls and 38 Claude calls. Compound calls can contain multiple subcommands. Two concrete syntax errors were `list --format json` and `list --names-only`; one missing-key error was also confirmed. Three Codex raw reads captured unmasked stdout directly. Nine Claude calls used the system Keychain CLI directly. Counts are not a model comparison: the samples differ in size and date range, and no claim about the exact model behind an individual session is made.

Private command bodies, values, key names, project names, and transcript files are not included here.

## Changes and verification

| Finding | Change | Regression coverage |
|---|---|---|
| Missing Keychain can open blocking macOS dialogs. An initial test harness triggered this by replacing `HOME`. | Preserve real `HOME` in runtime fixtures; disable Keychain UI for the AKM process; return `keychain_unavailable` with recovery guidance. | The exact missing-home case exits with JSON error within a bounded timeout. Normal Keychain operations still pass. |
| Ad-hoc signatures tie access to a particular binary; a rebuilt upgrade could no longer read existing keys. | Sign releases with a stable Developer ID; explicitly copy through the trusted old executable into a new namespace, preserving originals. | A real 0.1.3 synthetic item migrated, remained readable by the old binary, and was readable by the signed release. Different signed builds also shared access without UI. |
| The redactor held back ordinary output by the longest secret length and skipped short secrets. | Retain only a suffix that could become a secret; match all nonempty exact values and flush ordinary progress. | Child waits for input after printing a short line; parent must receive that line first. Short-value and every-chunk-boundary cases pass. |
| `stdin` could block writing input before draining verbose child output. Cancellation did not reliably reach descendants. | Shared subprocess runner drains output concurrently and forwards signals to a separate group for noninteractive jobs. | Large stdin plus 256 KiB child output, early stdin close, exit 42, and child/grandchild SIGTERM tests. |
| Default completion output added noise, and failures could look like success. | Completion is opt-in with `--json`; failures carry error status; runtime/parser errors use stderr. | Quiet-child, failed-spawn, child-exit, and parser contract tests. |
| Agents guessed unsupported options or fetched raw values to adapt transports. | Add names-only output, child environment aliases, env-formatted stdin, and scoped parser-derived discovery. | Mapping, raw/env stdin, discovery equality, and example parsing. |
| Bundled instructions demanded broad secret handling and automatic dotenv deletion. | Narrow the trigger and examples; remove unsolicited migration and deletion; add skill status and idempotent installation. | Isolated skill installation/status checks; source review. |
| Hook installation could replace another tool's hook; bare prefixes blocked examples. | Preserve foreign hooks and symlinks, honor Git's hooks path, require token-like text after prefixes. | Six staged-content and hook-preservation tests. |
| Export/import quoting did not reliably round-trip. Dry-run read Keychain. | Parse literal multiline and shell-quoted values without evaluating substitutions; preview names without Keychain access. | Quoted/multiline round trips, unterminated input, isolated-home preview. |
| Audit display loaded the entire historical file. CI invoked nonexistent library tests. | Read recent records backwards; skip oversized records; repair CI and add architecture/MSRV coverage. | Corrupt/partial/large log tests; release test matrix. |

## Size and interaction cost

Measured on one Apple Silicon Mac with optimized builds from pre-review 0.2.0 and the initial 0.3.0 candidate, before the migration command was added:

| Surface | Before | After |
|---|---:|---:|
| Bundled skill | 4,662 bytes | 1,556 bytes |
| Long help | 2,246 bytes | 1,785 bytes |
| Full discovery | 2,753 bytes | 7,481 bytes |
| Discovery needed for `run` | 2,753 bytes (full manifest only) | 2,096 bytes (scoped) |
| Stripped executable | 821,760 bytes | 871,792 bytes |

The skill is 67% smaller. Full discovery grew because it now describes the actual parser options and new behavior; scoped discovery avoids returning unrelated commands. The executable grew about 6%, so this is not a binary-size reduction. Ten warm local samples put metadata commands in the roughly 4–6 ms range; that small sample is not evidence of an end-to-end coding speedup. The meaningful runtime improvement is that ordinary progress no longer waits for secret-length buffering or child EOF.

## Compatibility and limits

Local validation passed on macOS 26.5.1, Apple Silicon, with Rust 1.98.1: formatting, warnings-as-errors Clippy, and 82 tests, including five end-to-end migration regressions. CI additionally targets macOS 26 Apple Silicon, macOS 15 Intel, and Rust 1.85. Release status should be checked against the linked GitHub workflow, not inferred from the presence of a matrix file.

The dependency moved from security-framework 2.11 to 3.7. Original items stay under `com.paperfoot.akm` in the file-based Keychain. New writes use `com.paperfoot.akm.v2`; `migrate --from` copies through a working older executable, verifies the destination, and preserves originals. It uses atomic create-only writes, so concurrent destination writes are not overwritten. New entries take precedence; `rm` deletes both copies. Developer ID signing preserves identity across release builds; arbitrary source builds still need stable signing or explicit access authorization. Apple's process-local UI setting is used for compatibility with that backend; it does not grant access or change Keychain ACLs. The underlying SecKeychain UI-setting API is deprecated in current SDKs but remains available for existing file-based Keychain clients. Moving to data-protection Keychain would require a separate entitlement/signing and migration design.

The existing `status: ok` envelope, plain-text help/version, and missing-key exit 6 are retained. This release borrows scoped discovery, explicit effects, parser-derived syntax, and recovery-oriented errors from agent-cli-framework. It does not claim full framework conformance: the framework's envelope/help contract differs, and its measurement tool rejects AKM's intentionally plain-text help.

Child output redaction is literal matching, not a general secret detector. Interactive terminal behavior can require `--no-redact`. SIGKILL cannot be handled; child processes that deliberately detach or ignore signals are outside the cancellation guarantee. The audit log remains best effort and does not record every failed pre-execution lookup. Imports can partially complete if Keychain fails midway. The explicit upgrade migration can partially complete and is resumable. Its legacy source process may still show its own Keychain UI; a five-second timeout stops the first blocked read. No existing project configuration is automatically migrated or deleted.
